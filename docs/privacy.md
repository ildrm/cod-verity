# Privacy and data ownership

WooCommerce owns orders, customer contact information, payment and stock data. CODVerity adds no plaintext phone/address/email copy. It stores order references, state, timestamps, a random seed, keyed token digest, keyed duplicate/content signatures, notification counters, resolution source, staff user ID/reason and operational events. Customer IP addresses are used only through keyed, two-minute rate-limit transients. No external analytics or hidden telemetry exists.

Duplicate matching uses phone digits, country, currency, amount and sorted product/variation quantities. A keyed HMAC avoids a plaintext phone copy. Keyed signatures remain pseudonymous personal data while linked to an order. Duplicate indicators are advisory and may include legitimate repeat purchases. Links in privileged order panels resolve through WooCommerce CRUD.

Transactional verification emails use the billing email already in the WooCommerce order and the site's configured `wp_mail` transport. Messages include first name, order number, total, deadline and bearer URL. That transport may use an independently configured third party. CODVerity itself adds no external provider. The merchant must disclose their actual email processing and decide the applicable operational/privacy policy.

Default audit retention is 90 days; resolved-request secret retention is 365 days. Bounded daily maintenance deletes old audit rows and scrubs seeds, fingerprints, staff IDs/reasons from resolved requests. Active requests are not pruned. Minimal order enrollment/status/timing rows remain to prevent automatic duplicate enrollment and preserve aggregate reporting; configure policy and process erasure requests as appropriate.

WordPress Tools → Export Personal Data exports matched billing-email request details in pages of 20 WooCommerce orders. Secret/hash material is excluded. Tools → Erase Personal Data stops active automation, excludes the order from future enrollment, removes the plugin operation marker and deletes matched request/events. Erasure never deletes the order or rewrites its status; a held order still needs review. If a request is busy the eraser reports retention so it can be retried. WooCommerce's own order/privacy policy is separate.

Deactivation preserves records/settings and leaves all order statuses intact. Uninstall preserves data unless the merchant explicitly enabled deletion. Destructive uninstall removes only plugin tables/options, plugin-prefixed transients, test cooldown user metadata and plugin order metadata through WooCommerce CRUD when WooCommerce is available. If WooCommerce is inactive and its CRUD is unavailable, harmless plugin order metadata remains; reactivate WooCommerce before destructive uninstall for full cleanup. No WooCommerce order is deleted.
